How a launch works

Last updated November 9, 2026

This is the launch flow at the level of individual calls and signatures. Nothing here is hidden from you on the page; this just names it.

Step 0. Before you start

  • A Solana wallet extension or app that can sign messages and transactions (Phantom, Solflare, Backpack).
  • Roughly 0.03 SOL for network costs, plus whatever you want to put into an optional initial buy.
  • A name (up to 32 characters), a ticker (1 to 10 letters or digits), a line of description, and a square image under 4 MB.

Step 1. Connect

Pressing Connect wallet calls the wallet's connect(). The page receives your public key and nothing else. It then reads your SOL balance from a public RPC and shows it under the launch bar so you can see the network cost is covered.

Step 2. Fill the form

  • Name and ticker are limited to what pump.fun accepts. The ticker is forced to upper-case letters and digits.
  • Art: a non-square still is centre-cropped to a square in your browser. If the file is over 95 KB it is also re-encoded as JPEG, stepping the quality down from 92% until it fits, so storage stays free. GIFs are never altered.
  • Options (closed by default): an initial buy in SOL with a live quote of tokens received and percent of supply; slippage (default 10%); a priority fee (default 0.0005 SOL) that speeds up inclusion; social links; a "pump" vanity suffix for the mint address; an optional Pinata key if you prefer IPFS.
  • The preview card on the right is rendered from the same values, so what you see is what the coin page will show.

Step 3. Press Fling it

The button only enables once a wallet is connected and the required fields are valid. From here the progress strip shows four stages.

3a. Store (signature 1 of 2)

  1. The page loads its vendored storage client and creates an Irys uploader bound to your wallet's public key.
  2. Your wallet asks you to sign a message. This is Irys's authorization for the upload; it is not a transaction and cannot move funds. The message is the upload's content hash and tags.
  3. The art is uploaded. Irys returns a content id; the image is now at https://gateway.irys.xyz/<id> and will be forever.
  4. A metadata JSON is built with your name, ticker, description, the image URL and any links, and uploaded the same way. Its URL becomes the coin's metadata URI.
  5. If a file is over 100 KB (only possible with a GIF), the page first asks Irys for the price, then asks your wallet to fund it. This is a tiny SOL transfer, a few thousand lamports.

3b. Build

  1. If you chose the vanity option, the page spawns web workers that generate keypairs until one's address ends in "pump". On a typical laptop this takes a few minutes; you can skip it. Otherwise a single keypair is generated instantly. Either way this is the coin's mint keypair, created in your browser and never sent anywhere.
  2. The page sends one request to PumpPortal's public trade-local endpoint: your public key, action: "create", the name, symbol and metadata URI, the mint public key, the initial buy amount, slippage, priority fee and pool: "pump". PumpPortal returns the bytes of an unsigned Solana transaction.
  3. The page signs the transaction with the mint keypair (the chain requires the mint to co-sign its own creation).

3c. Sign (signature 2 of 2)

Your wallet shows the transaction. It should simulate as: create a token, create its metadata, open the bonding curve, and (only if you set one) buy from the curve. You approve or reject.

3d. Confirm

The page sends the signed transaction through a list of public RPC endpoints, waits for confirmation at the "confirmed" commitment level, and then shows the mint address, the pump.fun page, the explorer page and the transaction. The coin is remembered in your browser's local storage under "Your launches" so you can find it again on this device. A ready-made post is offered for sharing.

What can go wrong, and what the page does

SituationWhat you seeWhat to do
Wallet rejects the message or the transactionA red status line; the progress strip clearsNothing was sent. Press Fling it again when ready.
Storage upload fails (network, size)A red status with the reasonRetry, or shrink the image; GIFs over 100 KB need a small payment.
Transaction builder refuses"Transaction builder refused: …" with the service's messageUsually a malformed symbol or a temporary outage. Fix the field or retry in a minute.
Transaction fails on-chain"Transaction failed on-chain" with the errorMost often slippage on the initial buy during a busy launch. Raise slippage or remove the initial buy and retry. Rent paid for failed account creation is returned by the runtime.
Confirmation times outStatus stays at "Confirming"Check the transaction link in an explorer; if it landed, the coin is live even though the page lost the confirmation.

Dry run

Add ?dry=1 to the page URL to run the whole flow without broadcasting. Storage and the transaction build happen for real; the final send is skipped. Useful for checking art and copy before a launch.
