1. Abstract

Launching a memecoin on Solana should take one form and one signature. In practice it takes accounts, API keys, pinning services, custom scripts, or a platform that quietly takes custody of the mint keypair and a cut of the curve. FLING is a static web page that does the whole job in the browser: it generates the mint keypair locally, stores the art and metadata permanently on Arweave with a signature from the launcher's own wallet, asks a public transaction builder for the pump.fun create instruction, and hands the transaction to the wallet to sign and send. Nothing is uploaded to a FLING server because there is no FLING server. The platform fee is zero.

2. The problem

pump.fun made the bonding-curve launch the standard way a memecoin is born on Solana: fixed supply, a deterministic price curve, no liquidity to seed, and an automatic migration to an AMM when the curve fills. The mechanism is good. The tooling around it is not:

  • Custody creep. Many "launchers" hold the mint key, the creator wallet, or both. The launcher ends up trusting a stranger's server with the one thing that proves they created the coin.
  • Key sprawl. Since pump.fun stopped accepting direct metadata uploads, programmatic launches need an IPFS pinning account and an API key. That is a sign-up, a secret, and a dependency that expires.
  • Opaque fees. Platforms layer a fee on top of pump.fun's fees and rarely show the full stack. Launchers find out at the end.
  • Broken metadata. Coins pinned to a free IPFS tier go dark when the pin lapses. The image on the coin page becomes a broken square forever.

3. Design principles

  1. Non-custodial, always. The page never sees a private key. The mint keypair is generated in the browser and used once. The wallet signs; the page only asks.
  2. Keyless by default. No account, no API key, no email. Storage is authorized by the launcher's wallet signature, not by a credential FLING holds.
  3. Permanent by default. Metadata and art live on Arweave, paid once, readable forever, so a coin page never rots.
  4. Zero platform fee. FLING adds nothing on top of pump.fun, PumpPortal and the network. If that ever changes it will be published on the fees page before it takes effect, never discovered after.
  5. Every fee named. The fees page lists every party that can take anything from a launch or a trade.
  6. Static and inspectable. The whole site is plain HTML, CSS and JavaScript in a public repository. What you can read is what runs.
  7. Minimal surface. One page, one form, options folded away. Depth lives in the documentation, not in the launch flow.

5. Launch lifecycle on pump.fun

A pump.fun coin follows a fixed path. FLING only handles the first step; the rest is the protocol.

5.1 Creation

The create instruction mints a fixed supply of 1,000,000,000 tokens and opens a bonding curve. Most of the supply is offered on the curve; the remainder is reserved for the liquidity pool the coin migrates into. pump.fun charges no creation fee; the network charges rent for the new accounts plus a transaction fee, together roughly 0.02 SOL. If the launcher adds an initial buy, it executes in the same transaction as the first trade on the curve.

5.2 The bonding curve

The curve is a constant-product market with virtual reserves. At launch the curve holds 30 virtual SOL against 1,073,000,000 virtual tokens. A buy of s SOL (after the trading fee) returns

tokens_out = T − (S · T) / (S + s)
where S = virtual SOL reserve, T = virtual token reserve

so the price rises smoothly with every purchase and falls with every sale, with no order book and no liquidity provider. Every trade on the curve pays pump.fun's trading fee of 1.25% (0.30% to the creator, 0.95% to the protocol, per pump.fun's published schedule). The quote shown next to the initial-buy field on the launch page uses exactly this formula.

5.3 Graduation

When enough SOL has been raised on the curve (the completion threshold set by pump.fun; historically about 85 SOL), the curve closes and the coin migrates to PumpSwap, pump.fun's own AMM, with the raised SOL and the reserved tokens seeding the pool. pump.fun charges a flat 0.015 SOL migration fee. After migration, swap fees follow PumpSwap's tiered schedule, which falls as the coin's market cap rises.

5.4 Creator revenue

The creator share of trading fees accrues to the wallet that created the coin, which with FLING is always the launcher's own wallet, because that wallet signed the create transaction. pump.fun lets creators direct that share to themselves, to holders, or to charity through its own interface; FLING does not sit in the middle of it.

6. Permanent metadata

A pump.fun coin's on-chain metadata points at a URI. If that URI dies, the coin's name still resolves but the image and description vanish from every explorer and trading interface. FLING stores both files on Arweave through Irys:

  • The art is centre-cropped to a square and, if needed, re-encoded until it is under 100 KB so it falls inside Irys's free tier. GIFs are left untouched to preserve animation; a GIF over the limit is paid for by the wallet at a few thousand lamports.
  • The metadata JSON follows the shape pump.fun and explorers read: name, symbol, description, image, showName, createdOn, and the optional twitter, telegram and website links.
  • Each upload is signed by the wallet. The signature authorizes the upload and ties the file to the launcher's public key; it cannot move funds.
  • Items are addressed by content id on Arweave and served through the Irys gateway. They cannot be edited or removed afterwards, which is the point.

Launchers who prefer IPFS can paste a Pinata key under Options; the page then pins to IPFS from the browser using that key and never transmits it anywhere else.

7. Economics

FLING charges nothing. Every other cost belongs to a named party and is listed on the fees page. The model is deliberately simple: FLING is infrastructure, not a toll booth. If a sustainable fee is ever introduced it will be a flat, disclosed amount shown on the launch form before the signature, never a hidden percentage of the curve.

8. Security model

  • No keys at rest. The mint keypair exists only in the page's memory for the seconds between generation and signing. It is never written to storage, never sent anywhere, and is discarded after the transaction is sent. (It is not needed again: a pump.fun mint has no further authority to exercise.)
  • Two explicit signatures. One message signature for storage, one transaction signature for creation. Your wallet shows both. If a third prompt ever appears, close the tab.
  • Nothing to phish on our side. There is no login, no seed-phrase field, no "import wallet". FLING will never ask for a seed phrase or private key, on the site or anywhere else.
  • Public code, pinned dependencies. The site, its single vendored storage bundle and its one CDN dependency (the Solana web3 library at a fixed version) are in the public repository.
  • Transaction you can read. Your wallet simulates the create transaction before you sign. It should show a token creation, the mint account, and (if you chose one) a buy; nothing else.

The full threat model is on the security page.

9. Roadmap

Planned, in order, none promised by a date:

  1. Hosted storage relay. An optional relay with a FLING-held pinning key for launchers whose wallets cannot sign messages. Irys stays the default.
  2. Mobile wallet flow. Deep links into mobile wallets so the whole launch works from a phone.
  3. Launch receipts. A shareable page per coin with the creation transaction, the stored metadata, and the creator wallet, so anyone can verify who launched what.
  4. Curve analytics. Live progress to graduation on the live board and on launch receipts.
  5. Templates. Reusable art and copy templates for teams that launch often.
  6. Languages. The launch page in the languages launchers actually use.

10. Operations and governance

FLING is operated by a small team under the FLING name. The site is deployed from a public repository through a reviewed, versioned pipeline; every change is a commit anyone can read. There is no admin key on-chain because there is nothing on-chain that belongs to FLING. Changes to fees, terms or privacy are dated at the top of each page.

11. The $FlingIt token

A $FlingIt token is planned. Its contract address will be published on the launch page at flingit.fun and on @FlingItFun before anywhere else; until it appears there, no token using the FLING or FlingIt name or the flick mark is affiliated with this site. The token's purpose, supply and distribution will be documented on this page before it launches, and the launchpad itself will keep working exactly as it does today, with no token required to launch a coin.
